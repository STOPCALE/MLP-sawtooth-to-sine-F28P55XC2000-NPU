## 0. 结论先行

| 问题 | 结论 |
|---|---|

| 那还优化吗？ | 优化 3 个可修的点（C1/C2/C3），**一次只改一个变量 + 过 CH22 回归**（§4）——**C1/C2/C3 已完成：12× → 2.6×** |

## 1. 口径统一：修掉"单位陷阱"（07 §6 遗留）

NPU 一次推理处理 **10 个点**，而 CPU 最初一次只处理 **1 个点** → 直接比是错的。
修复（CCS 提交 `fd1485b`）：

- **CH21 改为"CPU 推理 10 个点的耗时"** → 与 CH20 完全同口径
- VOFA 帧扩到 **33 通道**：新增 CH23..32 = CPU 的 10 点输出（与 CH10..19 逐点直观对比）

| 帧布局（33 通道） | 内容 |
|---|---|
| CH0..9 | 锯齿波输入 |
| CH10..19 | NPU 输出（QAT int8 模型） |
| CH20 | NPU 耗时 µs / 10 点 |
| CH21 | CPU 耗时 µs / 10 点（同口径） |
| CH22 | 开机自检最大误差（≈3.1e-2 为通过） |
| CH23..32 | 手写 CPU 输出（PTQ int8 模型，10 点） |

```

| 指标 | NPU | 手写 CPU | 比值 |
|---|---|---|---|
| 10 点耗时 | 560.3 µs | 6727.5 µs | **12.01×** |
| 每点耗时 | 56.0 µs | 672.8 µs | 12.01× |
| 每点周期数 | ≈8 405 | ≈100 913 | 12.01× |
| 周期/MAC | **2.0** | **23.9** | 12× |

两条重要附注：

1. **CPU 固定开销只有 ~2 µs（0.3%）**：早前按"1 点"测的 672 µs/点 与现在按"10 点"测的 672.8 µs/点几乎一样
   → 说明 12× 不是口径造成的幻觉，**是真差距**。
2. CPU 耗时 min/max 只差 0.1 µs（确定性的整数代码），NPU 波动 ~1 µs（DMA/调度抖动）。

**顺带（`--dump` 读到的一个量化细节）**：窗口输入 s=0.5336..0.5426 时，
NPU(QAT) 输出全为 −0.984375（= −63/64）；CPU(PTQ) 在第 5 个点跨了一格
（−0.995583 → −0.987744，差 0.007839 ≈ 恰好 1 个输出量化步）。
同一区间两个模型"落格"不同，属正常 1 LSB 级差异。

生成汇编（PC 上离线跑 cl2000，不烧板）：

  --include_path="E:\ccs\ccs\tools\compiler\ti-cgt-c2000_25.11.1.LTS\include" `
  --abi=eabi -k hand_infer.c
```

（产物 `hand_infer.asm` / `hand_infer.obj` 是**临时文件**，分析完已删，不入库）

> 📖 C1/C2 两轮优化的**完整过程**（汇编对照、C2 三稿迭代、方法论、自测题）
> 见 [09_汇编级优化实战](09_汇编级优化实战.md)。

`hand_quant_layer` 的内层循环（`-O2`）：

```asm
||$C$L2||:
        MOV       ACC,*XAR5++    ; ① 读 x[i]        (RAM)
        MOVX      TL,*XAR1++     ; ② 读 W_q[o][i]   (FLASH)
        SUBB      XAR7,#1        ; ③ 循环计数--（32位）
        SUBL      ACC,XAR0       ; ④ x[i]-z_in     （32位减）
        IMPYL     ACC,XT,ACC     ; ⑤ 乘法 —— 32×32！
        ADDL      P,ACC          ; ⑥ acc +=
        MOVB      ACC,#0         ; ⑦ \
        SUBB      ACC,#1         ; ⑧  | 每轮凭空造一个 32 位 -1
        CMPL      ACC,XAR7       ; ⑨  | 32 位比较
        B         ||$C$L2||,NEQ  ; ⑩ / 分支
```

三个发现（对应 C1/C2/C3 三个候选）：

1. **每 MAC 10 条指令，其中 4 条是循环控制**（⑦⑧⑨⑩）——循环下标用了 `int32_t`，
   编译器为它建 32 位递减计数器 + 每轮重造 -1 来比较；C28x 的 `BANZ`（减 1 跳转，1 条指令）没用上 → **C1**
2. **32×32 乘法**（`IMP YL`）——两个乘数实际只占 16 位
   （`x[i]-z_in ∈ [0,255]`，`W_q ∈ [-128,127]`），本可用单周期 `MPY`（16×16）→ **C2**
3. **每 MAC 一次 FLASH 读**（②）——`W_q` 在 FLASH，读延迟有 wait-state
   （有取指缓冲未必全暴露，靠 C3 实测说话）→ **C3**

⚠️ 诚实交代：10 条指令 ≈ 理论 10 周期，但实测 **23.9 周期/MAC** → 多出的 ~14 周期是
**停顿**（FLASH wait-state、乘法器延迟、流水线气泡），不全是指令条数的问题。
所以**别指望"压到 6 条指令就快 2.4 倍"**。

> **NPU 的 2.0 周期/MAC 是"乘加阵列 + 权重常驻"的架构产物，单发射流水线的 CPU 追不平。**
> 12× 这个结论是**结构性的**。

### 3.1 C1 实测：编译器换用了 RPTB 硬件循环（2026-10-07）

改动只有一个变量：`int32_t o, i;` → `int16_t o, i;`（累加器 `acc` 仍是 `int32_t`，不动）。

改后的内层循环（同一个 `-O2`）：

```asm
        RPTB      ||$C$L3||,AR6   ; <- 硬件循环：重复 N 次，零循环控制开销
||$C$L2||:
        MOV       ACC,*XAR0++     ; 读 x[i]          (RAM)
        MOVX      TL,*XAR7++      ; 读 W_q[o][i]     (FLASH)
        SUBL      ACC,XAR1        ; x[i]-z_in
        IMPYL     ACC,XT,ACC      ; 仍是 32×32 -> 留给 C2
        ADDL      P,ACC           ; acc +=
        NOP                       ; 流水线
        ; repeat block ends
```

**每迭代 10 条 → 6 条，且不再有"取分支"的流水线惩罚。**

| 指标 | v0 基线 | **C1** | 变化 |
|---|---|---|---|
| CPU 10 点耗时 | 6727.5 µs | **4374.6 µs** | **1.54×** |
| 周期/MAC | 23.9 | **15.5** | -35% |
| 比值 CPU/NPU | 12.01× | **7.82×** | — |
| CH22 | 0.0314 | 0.0314 | ✅ 无回归 |

> 为什么指令数 -40%，却只换来 1.54×？
> 剩下的 ~9.5 周期/MAC 是**停顿**：`IMP YL`（32×32 乘法）延迟 + 双数据读口压力 + 流水线气泡。
> **这正是 C2/C3 要打的。**

### 3.2 C2 实测：一条指令的 MAC 循环（2026-10-07）

目标：把 32×32 乘法（`IMP YL`）压成 16×16。**三稿才成**（每稿都在离线汇编里验证后取舍）：

| 稿 | 写法 | 编译器产物 | 结果 |
|---|---|---|---|
| ① 直接改 | `int16_t xs = x[i]-z_in; acc += xs*w;` | 9 条/迭代：MPYA + `MOV AL,AR3` + `MOVL` 存取对 + 3×NOP | ❌ 比 C1（6 条）还长 |
| ② 提 z 到局部 | 同上，z_in 先取到 `int16_t z16` | 依旧 9 条/迭代 | ❌ |
| ③ **提出零点半减** | `xs_buf[i]=x[i]-z_in` 先算好（层内不变式），内层只剩 `acc += xs_buf[i]*W[i]` | **`RPT AR5` + 单条 `MAC P,*XAR0++,*XAR7++`** | ✅ |

③ 的内层（每行）：

```asm
        MOV   P,#0                    ; P = 0 (MAC 累加器)
        MOVL  XAR0,#xs_buf
        RPT   AR5                     ; 单指令硬件重复 64 次（零取指!）
||      MAC   P,*XAR0++,*XAR7++       ; 循环体（"||" 是 RPT 的重复标记）: P += xs[i] × W_q[i]
        ADDL  ACC,P                   ; acc = b_int[o] + P
```

- `MAC P,loc,loc`：C28x 的**双内存操作数单周期 MAC**（DSP 看家本领）
- `RPT`：把**下一条指令**重复 N 次，期间零取指开销——比 RPTB 更极致
- 范围证明（已写进代码注释）：`xs∈[-128,255]`、`W_q∈[-128,127]` → 乘积 ⊂ int16，16 位通路无损

| 指标 | v0 | C1 | **C2** | 变化（vs C1） |
|---|---|---|---|---|
| CPU 10 点耗时 | 6727.5 | 4374.6 | **2326.7 µs** | **1.88×** |
| 周期/MAC | 23.9 | 15.5 | **8.3** | — |
| 比值 CPU/NPU | 12.01× | 7.82× | **4.03×** | — |
| CH22 | 0.0314 | 0.0314 | 0.0314 | ✅ 无回归 |

**累计（v0 → C2）= 2.89×**，比值 12.0× → 4.0×。

> 还没到理论极限：理想情况 L1 每行 ≈ setup 12 条 + MAC 64 周期 + requant ~25 条 ≈ 110 周期
> → 64 行 ≈ 7k 周期/点；实测 **34.9k 周期/点**（8.3×4224）→ 还有 ~3.5× 没挖出来。
> 嫌疑：**W_q 从 FLASH 读的等待周期** + FPU/流水线停顿 —— 这正是 C3 的靶子。

## 4. 优化候选（一次只改一个！）

| # | 改动 | 汇编依据 | 预期 | 风险 |
|---|---|---|---|---|
| **C1** | 循环下标 `int32_t i/o` → `int16_t` | ③⑦⑧⑨⑩ | ✅ **实测 1.54×**（12.0×→7.8×，见 §3.1） | 已完成 |
| **C2** | `(int32_t)x*W` → 16×16 MAC；零点半减提出内层（`xs_buf`） | ⑤ `IMP YL` | ✅ **实测 1.88×**（7.8×→4.0×，见 §3.2） | 已完成 |
| **C3** | `W_q` 搬 RAM（去 const + `DATA_SECTION`→ramgs1/2，`.cinit` 拷贝） | ② FLASH 读 | ✅ **实测 1.57×**（4.0×→2.6×，见 09 §4） | 已完成 |

| 进阶 | int32 定点乘子 `M0·2^-shift` 替代浮点 M | — | 去掉重定标里的全部浮点 | 中（要写乘子计算工具） |
